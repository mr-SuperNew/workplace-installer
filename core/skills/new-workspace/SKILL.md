# Новая папка задачи и приём проекта

Одна задача, одна папка, свой чат. Папка задачи живёт в `workspaces/<имя>/` главной папки. Существующий проект остаётся там, где он лежит, или лежит там, куда его скопировал человек: оба случая принимаются.

## Что просит человек

- «Заведи папку под новую задачу»: шаги ниже, вариант А.
- «Работаем с проектом, он лежит в `<путь>`»: вариант Б (на месте).
- «Я скопировал проект в главную папку, продолжай»: вариант В.
- «Скопируй проект в главную папку»: вариант Г.

## А. Новая задача

1. Выясни у человека две вещи, если их нет: как назвать папку (латиница, цифры и дефис, например `weekly-report`; русское название тоже годится, имя получится транслитом) и какая у неё цель одной фразой.
2. Посмотри `ls workspaces`. Есть похожая по смыслу: покажи человеку и предложи продолжить в ней. Команда ничего не перезапишет, но две папки на одну задачу путают.
3. Создай папку из главной папки:

```
node .workplace/core/cli/wp.js new-workspace <имя-латиницей> --title "Название по-русски" --goal "Цель одной фразой"
```

Команда создаёт `AGENTS.md`, `CLAUDE.md` (строка `@AGENTS.md`), `tasks.md`, `MEMORY.md` по шаблонам, `handoffs/`, `data/` (входные данные), `out/` (результаты). Папка уже есть: команда ничего не перезаписывает и говорит об этом (код 3); продолжи в существующей.

4. Допиши в `workspaces/<имя>/AGENTS.md` частности задачи, если человек их назвал. Общие правила не дублируй.
5. Добавь в корневой `tasks.md` строку про новую папку.
6. Скажи, как войти: главная папка остаётся открытой (сторожа, навыки и правила лежат в ней); для задачи начни новый чат и скажи «работаем в workspaces/<имя>».

Проверка: `ls workspaces/<имя>` показывает `AGENTS.md`, `CLAUDE.md`, `tasks.md`, `MEMORY.md`, `handoffs`, `data`, `out`.

## Б. Проект лежит на компьютере, работаем на месте

1. Прочитай проект: `README`, структуру папок, главные файлы, `git status` и `git log -5`, если есть `.git`. Расскажи человеку коротко, что он делает.
2. Принять проект: `node .workplace/core/cli/wp.js adopt <путь>`. Команда не меняет сам проект. Она записывает проект в память главной папки и заводит под него папку задачи с путём проекта.
3. Перед первой правкой в проекте: скажи, что будешь править файлы в `<путь>`, сделай копию (`node .workplace/core/cli/wp.js backup <путь>`, для git-проекта запиши ещё текущий коммит в `MEMORY.md` папки задачи), зарегистрируй план (`wp.js consent plan "..."`) и получи «да». Дальше правь без повторных вопросов, пока человек не назвал другой проект.
4. Только читать и рассказывать: «да» и копия не нужны, ничего не меняй.

## В. Проект уже скопирован в главную папку

1. Выполни `node .workplace/core/cli/wp.js adopt <путь>`. Если у проекта свой `.git`, команда дописывает его папку в `.gitignore` главной папки, чтобы коммит главной не захватил чужую историю. Нет команды или она не сработала: допиши в `.gitignore` строку с папкой проекта (например `my-shop/`) и проверь `git status` в главной папке: проект там быть не должен.
2. Копия не нужна: оригинал остался там, откуда человек его взял. Начинай работу: прочитай проект, продолжай с того места, которое назвал человек.
3. Свой `AGENTS.md` или `CLAUDE.md` проекта читай как правила проекта и не перезаписывай. Правила главной папки действуют вместе с ними.

## Г. Копия проекта внутрь главной папки

Человек просит копию с историей git: модуль `.workplace/modules/migrate-project/` (README рядом). Он делает резервную копию, копирует проект вместе с историей в `projects/<имя>`, сверяет и записывает итог в `STATE.md`. Просьба человека и есть команда запускать: покажи план (`copy` без `--yes`), потом выполни с `--yes`. Простой проект без истории можно скопировать обычной командой копирования; после этого вариант В.

## Не забудь

- Проект не пустой и не твой: перед правкой читай файл целиком.
- Нашёл в проекте `.env` или ключи: используй их в программах, но значений не печатай и в git не клади.
- Удалить исходный проект после копии можно по просьбе человека: полный путь и «да».

# Доктор рабочего места

Говори по-русски, коротко, термины поясняй. Порядок: проверка, починка, повторная проверка. Человек написал «починь», «не работает», «исправь» или `/doctor` с жалобой: чини сразу после проверки. Попросил только «проверь»: покажи таблицу и предложи починку одной строкой.

## Проверка

```
node .workplace/core/skills/doctor/scripts/doctor.js
```

Скрипт ничего не пишет и не ставит. Он показывает таблицу «ок / НЕТ / не проверено»:

- Node, Python, git;
- **оба ИИ независимо от роли**: консольная команда, версия, вход в аккаунт; направление «основной делает, второй проверяет» и обратное (возможно ли оно сейчас);
- вход определяется ответом самой программы (`codex login status`, `claude auth status`), а не командой `claude doctor`: она отвечает «всё хорошо» и без входа. Вход по ключу API помечается как неверный (платный, для подписки не годится);
- правила, память, `.gitignore`, `config.json`;
- сторожа: подключены в оба ИИ и отвечают на тестовый ввод (мусор молчит, выдуманный пароль останавливается, команды установки не мешают);
- навыки одинаковы в `.claude/skills` и `.agents/skills`;
- **самопроверка кросс-чека с вшитой ошибкой**: верная копия получила GREEN, копия с ошибкой RED с названной ошибкой.

Для каждого «НЕТ» скрипт печатает строку «починка: …». Коды выхода: 0 всё хорошо; 1 есть провал; 2 провалов нет, но часть проверок не выполнена (это не зелёное).

Вход в Claude Code проверяет `claude auth status`: команда создаёт служебные файлы в `~/.claude`. Скажи об этом одной фразой и запусти скрипт с `--live`. Вход в Codex проверяется всегда, файлов он не создаёт. Для одного этапа: `node .workplace/core/cli/wp.js verify P1.node`; список этапов: `node .workplace/core/cli/wp.js state show`.

## Починка

Для каждого «НЕТ» возьми команду из строки «починка», покажи человеку, что она сделает и откуда ставит, и действуй:

- программа не стоит (`install.claude`, `install.codex`, Python, git): установка идёт по «да» человека (покажи источник и команду): `node .workplace/core/cli/wp.js install <claude|codex|python|git> --yes --human-said "слова человека с «да»"`. Официальный установщик, при неудаче запасной путь npm без `sudo`. Пароль компьютера вводит человек, если система его спросит;
- нет входа в аккаунт: вход делает человек в браузере (`claude` или `codex login`, без браузера `codex login --device-auth`); дай команду и объясни, пароль он вводит сам. После входа повтори проверку;
- нет правил, навыков, копий: `node .workplace/core/cli/wp.js layout` (файлы человека не перезаписываются, различия печатаются как «ОТЛИЧАЕТСЯ»);
- сторожа не подключены: `node .workplace/core/cli/wp.js hooks wire`; не отвечают на тест: `hooks test` покажет, какой;
- навыки отличаются от пакета: `layout --update` заменит копии навыков копиями из пакета; копию прежнего файла команда кладёт в `.workplace/backups/` сама (путь печатает). Если человек правил навык, скажи ему об этом и где копия;
- самопроверка не пройдена или не делалась: `node .workplace/core/skills/cross-check/scripts/selftest-run.js` (два запуска проверяющего тратят его лимит; скажи об этом). Если ошибочная копия получила GREEN или ошибка не названа, проверка слепая: скажи человеку «проверка не работает», разберись, почему, и чини, результат не подгоняй;
- ошибка, которой нет в таблице: загляни в `.workplace/docs/troubleshooting.md`, прочитай журнал и текст ошибки, найди причину, предложи починку и сделай её. Установка и удаление идут через «да».

Каждый результат отметь: `node .workplace/core/cli/wp.js state set <этап> done|failed --note "..."`.

«Продолжи установку»: `node .workplace/core/cli/wp.js state next` покажет первый незавершённый этап; иди с него.

## Повторная проверка и отчёт

После починки снова запусти `doctor.js` и покажи итоговую таблицу. Человек просит отчёт об установке: `node .workplace/core/cli/wp.js report` (путей с именем пользователя и ключей в нём нет), покажи, что внутри. Отправлять отчёт автору необязательно: если человек захочет, ссылка в конце отчёта.

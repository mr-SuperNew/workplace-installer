# Ошибка: что делать

**Коротко:** файл для ИИ, который ставит и чинит рабочее место, и для человека, который читает за ним. Идите по разделу того этапа, который не получился. Первый способ не помог: пробуйте другой, одну и ту же команду больше двух раз подряд не повторяйте. Ошибки нет в таблице: найдите причину по тексту ошибки и журналам, объясните человеку простыми словами, что случилось, и предложите следующий шаг. Пометка «проверить на месте» значит: официальные страницы это не подтверждают, проверьте результат сами и скажите человеку, что получилось. Всё, что человек делал руками, записывайте: `node .workplace/core/cli/wp.js state manual "что сделал"`. В ячейках таблиц `\|` означает обычную вертикальную черту `|`, в команде пишите `|`.

Коды выхода `wp.js`: 0 готово; 1 ошибка или провал проверки; 2 неверные параметры, есть расхождения или нужен `--yes`; 3 отказ (чужая папка, запись вне главной папки); 4 нужны имя и почта для git; 5 Node старше 18; 6 git недоступен.

## Общее (любой этап)

| Что видишь | Что делать |
|---|---|
| `command not found` или «не распознано как команда» сразу после установки | Это старое окно со старым PATH. Mac: новое окно Терминала и `command -v имя`. Windows: новое окно PowerShell и `where.exe имя`. Видно там: вызывай программу по полному пути или попроси человека перезапустить окно, потом написать «продолжи установку». Не видно и там: допиши PATH в профиль. Для программ установщика это `wp.js path-fix --yes --human-said "слова человека с «да»"`, он входит в план установки. Другую строку PATH по просьбе человека: копия профиля, разница, «да», правка (см. `install-steps/mac.md`, `windows.md`, раздел «Правило PATH») |
| Окно с просьбой пароля компьютера или окно UAC | Объясни одной фразой, зачем оно. Пароль вводит и окно нажимает человек. Сам ничего не вводи |
| Установщик просит `sudo` | Пароль вводит человек. Дай ему команду, объясни, что она делает; запускает он. Для npm вместо `sudo npm install -g` бери префикс в домашней папке (`wp.js install codex --yes --human-said "слова человека с «да»" --npm`) |
| Установщик сам дописал строку в `~/.zprofile` или `~/.zshrc` | Это нормально: так делают установщики Claude Code, Codex и Homebrew. Скажи человеку, проверь, нет ли дублей строки PATH. Откат по «да» |
| Команда долго молчит | Установщик Claude Code прогресса не показывает. Подожди, второй раз не запускай |
| `curl` пишет `syntax error near unexpected token '<'` или `403` | Покажи человеку, открой https://code.claude.com/docs/en/troubleshoot-install; не повторяй много раз подряд. Запасной путь для Claude Code: `brew install --cask claude-code` (если Homebrew уже есть) или `winget install Anthropic.ClaudeCode` |
| Claude Code, Codex или сторож остановили действие и просят подтверждение | Это просьба о «да». Покажи человеку, что именно собираешься сделать (путь, команда), и спроси «да». Пароли и коды вводит он сам |
| macOS спрашивает доступ Терминала или VS Code к папкам «Документы», «Рабочий стол», «Загрузки» | Это системный запрос, решает человек. Проще держать главную папку в домашней папке вне «Документов» и iCloud (проверить на месте) |
| macOS: «приложение повреждено» или «нельзя проверить разработчика» | В пакете нет файлов для двойного щелчка. Если такой файл есть, запусти его командой `bash путь`: проверка Gatekeeper работает только на запуск из Finder. Запасной путь: Системные настройки, «Конфиденциальность и безопасность», «Всё равно открыть» (проверить на месте) |
| `node` не найден или старше 18, `wp.js` отвечает кодом 5 | Ставится Node по шагу 4 файла `INSTALL.md`. Команды без Node: `docs/recon-without-node.md` |
| Не знаю, что делать | Не придумывай. Опиши человеку, что видишь, назови две-три возможные причины и предложи следующий шаг; запиши в `tasks.md` |

## Доверие папке и панель Claude (VS Code, модуль vscode)

| Что видишь | Что делать |
|---|---|
| Значка (искры) Claude нет, панель не открывается, на панели «untrusted workspaces are not supported» или внизу слева плашка Restricted Mode («Ограниченный режим») | Папка не доверена. Нажать на плашку, затем «Trust» или «Доверять» («Yes, I trust the authors»). Через меню: Cmd или Ctrl+Shift+P, «Workspaces: Manage Workspace Trust». Каждая новая папка спрашивает заново: это штатно |
| Значок не появился и после Trust | Cmd или Ctrl+Shift+P, набрать «Claude Code», выбрать «Open». Не помогло: закрыть VS Code полностью и открыть ту же папку |
| Человек открыл меню «Open Agent», «Open in Agents», «Build with Agent» | Это встроенный GitHub Copilot, не Claude. Панель Claude: значок-искра справа вверху или Cmd или Ctrl+Shift+P, «Claude Code: Open» |
| «The terminal process failed to launch» в панели терминала VS Code | Не блокирует: у Claude свой шелл. Запиши в `state manual`; причину не выясняй. Команды человек вводит в системном терминале |
| Вход в Claude открылся не в том браузере | Человек копирует адрес со страницы входа и открывает его в нужном браузере |

## Разведка и случай

| Что видишь | Что делать |
|---|---|
| Таблица показывает «консольный codex: нет», а расширение Codex есть | Так и должно быть: это разные вещи. Консольный Codex ставится по плану после «да» |
| Две и больше копии `claude` или `codex` | Не ставь третью. Покажи человеку, какая запускается первой (`which -a claude`, Windows `where.exe claude`), версии и откуда. Удаление лишней копии по его «да» на конкретную копию. Решение запиши в `state note` |
| Версия Claude Code ниже рекомендуемой | Это совет, не блокер: правила подключены через `CLAUDE.md` и `@AGENTS.md`, и это работает на старых версиях. Обновление предложи, выполняй с «да»: `claude update` для родной копии (`~/.local/bin`), для остальных копий тем способом, которым они поставлены |
| macOS ниже 13 | Предупреждение, не остановка. Claude Code официально поддерживает macOS 13 и новее. Проверь живой пробой, что программа отвечает |
| `git` или `python3` просит поставить Command Line Tools | Это системное окно, не ошибка. Не запускай их до `xcode-select -p`; поставь Command Line Tools по шагу «git» ниже |
| Python на Windows «есть», но по пути `WindowsApps` | Это заглушка магазина, Python не стоит. Проверка `py -3 --version` |

## git

| Что видишь | Что делать |
|---|---|
| Mac: `git` просит установить Command Line Tools | Системное окно, делает человек: `xcode-select --install`, «Установить», 5 до 15 минут. Повтори `xcode-select -p` |
| Windows: `git` не найден | `winget install -e --id Git.Git`, потом новое окно. Нет winget: установщик с git-scm.com (делает человек) |
| «dubious ownership» | Папка принадлежит другому пользователю (часто из-за `sudo`). Скажи человеку, не используй `sudo`; проверь владельца командой `ls -ld .` |
| В `git status` главной папки виден `.env` или `data/` | Не делай `git add`. Выполни `wp.js gitignore check`, дополни `.gitignore` (`wp.js gitignore append`), проверь `git status` ещё раз и скажи человеку |
| `git-init` просит имя и почту (код 4) | Спроси человека одной просьбой. Имя и почта пишутся только локально в `.git` главной папки |
| Нет git, а основной ИИ Codex | Сторожа Codex работают, когда в корне папки есть `.git`. Предложи поставить git (по «да»); без него сторожа работают при запуске из самой главной папки |

## Node.js и Python

| Что видишь | Что делать |
|---|---|
| Нет Node, Homebrew уже стоит и поддерживается (Apple Silicon, macOS 15 или новее) | `brew install node` |
| Нет Node, Mac без Homebrew или Mac, который Homebrew не поддерживает (Intel, macOS ниже 15 на Apple Silicon) | Официальный архив с nodejs.org в `~/.local/node`, пароль не нужен: `bash ПАКЕТ/core/scripts/install-node-user.sh` (сначала `--dry-run`, после «да» без него). Homebrew не ставь: на таком Mac пакеты Node может собирать из исходников часами. Windows: `winget install -e --id OpenJS.NodeJS.LTS` |
| Скрипт Node остановился с кодом 3 («контрольная сумма не совпала») | Ничего не распаковано. Не повторяй много раз: покажи человеку обе суммы. Чаще это обрыв загрузки или прокси провайдера, реже подмена; сумма берётся с того же сайта, поэтому она ловит битый файл, но не взлом самого сайта |
| Скрипт Node: «macOS слишком старая» | У Node 22 и новее минимум macOS 11 (Node 24: 13.5). Скажи человеку простыми словами, выбор за ним: обновить macOS или поставить установщик .pkg более старой версии Node вручную |
| `node` не найден в новом окне после установки архивом | Папка `~/.local/node/bin` в PATH не записана. После «да» человека: `~/.local/node/bin/node .workplace/core/cli/wp.js path-fix --yes --human-said "слова человека с «да»"`, затем новое окно терминала и перезапуск программы ИИ (сторожа запускают `node` по PATH) |
| `node` старше 18 | Обнови по «да» человека: новая версия станет Node для всех его проектов. Тем способом, каким он установлен (`brew upgrade node` или новый установщик) |
| `brew install node` падает на Command Line Tools | Вернись к шагу git, поставь Command Line Tools. Если Mac на Intel или на macOS ниже 15, Homebrew для него не поддерживается: используй архив (строки выше) |
| Нет Python на Mac без поддерживаемого Homebrew | `xcode-select --install` (системное окно, человек нажимает «Установить», 5-15 минут; ставит и python3, и git). До появления пути у `xcode-select -p` не запускай `python3` и `git`: это заглушки. Потом `wp.js verify P1.python`. Запасной путь: установщик со страницы https://www.python.org/downloads/macos/ (двойной щелчок и пароль) |
| Нет Python | `wp.js install python --yes --human-said "слова человека с «да»"`. Идентификатор winget `Python.Python.3.13` проверен `winget search Python.Python` 21.10.2026; если он исчез из списка, найди актуальный той же командой |

## Claude Code

| Что видишь | Что делать |
|---|---|
| `claude: command not found`, а расширение работает | У расширения своя копия внутри `~/.vscode/extensions/anthropic.claude-code-*`. Консольная команда нужна для основного Claude и для проверяющего Claude: `wp.js install claude --yes --human-said "слова человека с «да»"` |
| `claude update` не проходит (нет прав на системную папку) | Не используй `sudo`. Поставь родную копию в домашнюю папку (`wp.js install claude --yes --human-said "слова человека с «да»"`), дальше как для двух копий |
| Версию встроенной копии видно в имени папки `~/.vscode/extensions/anthropic.claude-code-ВЕРСИЯ` | Она обновляется самим VS Code (вкладка расширений, «Обновить») |
| Вход в Claude не прошёл | Человек запускает `claude auth login` или пишет в панели `/login`, выбирает «Claude.ai Subscription». Нужен платный тариф Pro или выше |
| `claude auth status` создал файлы в `~/.claude` | Так и есть: эта команда создаёт файлы настроек. Она запускается при проверке входа (`/doctor --live`, шаг 7 установки); при разведке не вызывается |

## Codex CLI

| Что видишь | Что делать |
|---|---|
| `codex: command not found` | Новое окно терминала; `which -a codex` (Windows `where.exe codex`) и `ls ~/.local/bin`. Лежит вне PATH: вызывай по полному пути или допиши PATH (`wp.js path-fix --yes --human-said "слова человека с «да»"`, он входит в план установки) |
| Установка | `wp.js install codex --yes --human-said "слова человека с «да»"`. Вручную: Mac `curl -fsSL https://chatgpt.com/codex/install.sh \| sh`; Windows `powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 \| iex"`; запасные `npm install -g @openai/codex` и `brew install --cask codex` |
| npm просит права (EACCES) | Без `sudo`: `wp.js install codex --yes --human-said "слова человека с «да»" --npm` повторит установку с префиксом в домашней папке |
| Codex отвечает «blocked by policy» на удаление папки в PowerShell, хотя человек сказал «да» | Это правило самого Codex, не сторожей пакета: в неинтерактивном режиме он отклоняет `Remove-Item` с `-Force`. Удаляй без него: `Remove-Item -LiteralPath 'полный путь' -Recurse`. Путь пиши полным, без переменной, которую не задал в той же команде |
| Расширение Codex в VS Code есть, а команды `codex` нет | Это разные вещи. Проверяющему нужна консольная команда. Поставь её; вход общий, если `CODEX_HOME` не менялся |
| Mac Intel: бинарник не запускается («Bad CPU type», «dyld» и подобное) | Запиши текст ошибки дословно в `state note` и в отчёт, покажи человеку. Запасной путь через npm |

## Входы в аккаунты

Одна просьба человеку за сообщение. Сначала что сделать (открыть терминал, вставить команду), потом ждать «готово».

| Что видишь | Что делать |
|---|---|
| `codex login status` не показывает вход | Запусти `codex login`: откроется браузер, человек входит в ChatGPT. Нет браузера: `codex login --device-auth` (код вводится на странице; вход по коду нужно включить в настройках безопасности ChatGPT) |
| Проба `codex exec` отвечает про вход или 401 | То же: `codex login`, потом одна повторная проба |
| Ответ про лимит или квоту | Повтор не поможет: лимит возвращается со временем. Скажи человеку, что проверка ждёт лимита, и предложи выбор: подождать или идти без проверки по его слову (в итоге пометка «не проверено вторым ИИ»). Своей проверкой вместо второго ИИ не называй. Этап `skipped` с причиной |
| `codex login status` показывает вход по ключу API | Это платный вход, подписке он не нужен. Попроси человека войти по подписке ChatGPT: `codex logout`, потом `codex login` |
| Задана переменная `CODEX_HOME` | Не менять: вход лежит в её папке |
| Вход в Claude: в окружении задан `ANTHROPIC_API_KEY` | Проверяющий Claude при заданном ключе пойдёт по платному ключу, а не по подписке. Скажи человеку, ключ из окружения проверки убирается |
| Нужна подписка | Claude Code: Pro или выше. Codex: Plus или выше (бесплатный план даёт малый лимит) |

## Раскладка (`layout`)

| Что видишь | Что делать |
|---|---|
| Команда пишет «ОТЛИЧАЕТСЯ, не перезаписан» | Файл уже был и отличается от шаблона. Покажи человеку различие. Файлы пакета и навыки заменяет `layout --update`: перед заменой команда сама кладёт копию прежнего файла в `.workplace/backups/` (путь печатает); скажи человеку, что заменяешь, и где копия |
| `CLAUDE.md` уже есть и без строки `@AGENTS.md` | Не перезаписывай и не удаляй. Предложи дописать `@AGENTS.md` первой строкой (с «да»): без неё правила `AGENTS.md` не загрузятся у Claude |
| `.gitignore` уже есть, не хватает строк | `wp.js gitignore append`, до первого `git add` |
| `settings.json повреждён` | Сохрани копию `settings.json.bak`, покажи человеку, что повреждено, и создай файл заново (`hooks wire`) |
| В `~/.claude/skills` есть личный навык с таким же именем (`cross-check`, `doctor`) | Личный главнее проектного. Скажи человеку; личный навык он может переименовать сам, а ты по его «да» (копия, правка) |
| `init` отказал: папка не пуста или внутри чужого проекта | Предложи другое новое место, например `~/workplace-2`. Ничего не создано и не изменено |

## Сторожа и перезапуск

| Что видишь | Что делать |
|---|---|
| Нет навыков `/cross-check` и `/doctor` | Выполни `/reload-skills` или перезапусти программу целиком. Проверь, что открыта главная папка (в ней `.claude/skills`) и она доверена |
| Нет признака хука старта сессии в контексте | Хук не сработал: `node .workplace/core/cli/wp.js hooks status`, `hooks test`, `node --version`. Claude Code мог спросить доверие к хукам проекта: человек отвечает «да» |
| Тестовая запись выдуманного пароля прошла | Удали свой тестовый файл. Сторож не подключён или не загружен: `hooks wire`, `hooks status`, перезапуск (VS Code закрыть целиком, терминал закрыть и запустить ИИ снова в главной папке), «продолжи установку», проверка заново |
| Основной ИИ Codex, сторожа не срабатывают | Нужны два условия: в корне главной папки есть `.git`, и проект доверен Codex. Постоянное доверие даёт человек командой `/hooks` в Codex (разовый шаг) |
| В контексте нет `AGENTS.md` у Claude | Проверь, что `CLAUDE.md` в корне начинается со строки `@AGENTS.md`; полный перезапуск |

## Самопроверка с вшитой ошибкой (`/cross-check`)

| Что видишь | Что делать |
|---|---|
| Ответ про разрешения или «не удалось прочитать файл» | Один повтор; потом покажи человеку журнал запуска (путь в SKILL.md навыка) |
| `verdict.md` пуст или нет строки `ВЕРДИКТ:` | Статус «НЕ ПРОВЕРЕНО». Смотри журнал: вход, лимит, песочница |
| «НЕ ПРОВЕРЕНО: нет верной цитаты» | Проверяющий не прочитал файл или выдумал цитату. Один повтор; потом покажи человеку |
| Вердикт с `???` вместо русских букв | Вердикт не принимается. Один повтор; если снова, объясни человеку причину (кодировка вывода проверяющего) и предложи запуск на английских отчётах |
| Проверка с ошибкой вернула GREEN | Среда не принята: проверка слепая. Не говори, что проверка настроена. Найди причину по журналу запуска проверяющего, почини и повтори самопроверку; если не вышло, покажи человеку оба вердикта |
| Проверка идёт дольше 10 минут | Для больших проверок нормально (до 25 минут). Запускай в фоне, второй запуск не начинай |
| Отказ: «похоже на ключ или пароль» | Так и задумано: файл с секретом проверяющему не уходит. Убери секрет из файла или замени его заглушкой в копии |
| Отказ: формат не передаётся | Word, Excel, PDF и картинки не читаются. Сохрани как `.md`, `.csv` или `.txt` |
| Отказ: «Абсолютные пути не принимаются», «Путь с `..`», «ссылка» | Скрипты работают с файлами внутри главной папки. Файл из другого места скопируй в `workspaces/review-copies/data/` и передай путь копии (см. `/cross-check`) |
| Проверяет Claude, основной Codex: `run-check.js` отвечает «нет сети» | Песочница основного Codex без сети, а скрипт не может включить её тому процессу, который его запустил. Нужна настройка Codex `sandbox_workspace_write.network_access = true`: `wp.js layout` пишет её в `.codex/config.toml` главной папки (проверь `verify P2.core`), после этого Codex перезапускают в доверенной папке. Запасной путь: запустить основной Codex с флагом `-c sandbox_workspace_write.network_access=true`. Работает ли `config.toml` проекта так же, как флаг, на живом Codex не проверено (TODO: verify). Нет сети и после этого: скажи человеку, что проверка Claude из Codex ждёт сети, и предложи поменять роли (`wp.js role set claude`: проверять будет Codex) |
| `verify P3.selftest` красный: «нет доказательства, что проверяющий запускался» | Вердикт не от `run-check.js` (нет `run.json` или хеш не совпал): так бывает, если `verdict.md` писали руками или правили. Повтори `selftest-run.js`: вердикт руками не пишется, запись в эти файлы сторож останавливает |
| Проверка настройки: RED «нет защиты .env» | Ложная находка: защита стоит хуком сторожа секретов. Добавь в запрос, что это сделано намеренно |

## Записи вне главной папки (`snapshot diff`)

Записи делятся на три класса: сделанные установщиком, штатные записи программ и файлы, которые мог менять человек или VS Code. Подробно: [global-writes.md](global-writes.md).

| Что видишь | Что делать |
|---|---|
| `[B] штатно` (журналы и кэш Claude Code и Codex, `~/.codex/auth.json`, `~/.claude.json`, `~/.npm`) | Нормально. Попадёт в отчёт одной строкой |
| `[D] объявлено` (PATH в профиле, `~/.local/bin`) | Нормально: это запись официального установщика, о которой сказали заранее. Проверь дубли строк |
| `[C] вопрос: это вы меняли?` (настройки VS Code) | Спроси человека. VS Code сам пишет свои настройки (Trust, перезапуск). Названия изменённых ключей напечатаны, значения нет |
| `[A] ТРЕВОГА` (запись, которую никто не объявлял; профиль оболочки, `~/.claude/settings.json`, `~/.codex/config.toml`, подозрительные ключи VS Code, `keybindings.json`) | Покажи человеку запись дословно, объясни, что она может значить, и запиши в `state note`. Откат по его «да»: скопировать файл из `.workplace/snapshots/before-files/` поверх изменённого |
| «Нет снимка до» | Выполни `snapshot before` (он снимается при `init`; повторно с `--force`) |

## Обновление (`update`)

| Что видишь | Что делать |
|---|---|
| «update запускается только из нового пакета» | Распакуй новый архив отдельно, вне главной папки, и запусти скрипт оттуда: `node НОВЫЙ_ПАКЕТ/core/cli/wp.js update plan --root ГЛАВНАЯ` |
| `update apply`: «сторож не видит сообщений человека» или «в последнем сообщении человека нет «да»» или «нет слова «обнови»» | Флаг `--yes` «да» не заменяет, его берут из сообщений человека. Покажи человеку план (`update plan`) и дождись его «да»; в двух последних его сообщениях должно быть «обнови»/«update» или версия пакета. Чтобы одно «да» покрыло показанный план: `node ГЛАВНАЯ/.workplace/core/cli/wp.js consent plan "обновляю до ВЕРСИИ: …"`, потом вопрос «да». Нет записей совсем: хук не подключён или не доверен (у Codex команда `/hooks`, проверка `wp.js hooks status`), тогда команду выполняет сам человек. `--human-said` у `update` не принимается |
| В плане «ОТЛИЧАЕТСЯ» | Ты или человек правили файл пакета (хеш не совпал с записанным в `state.json` при установке). Он не заменяется сам: покажи человеку разницу и после его «да» на этот файл (он называет имя или путь файла, либо файл стоит в зарегистрированном плане) добавь `--overwrite путь,путь`. Назвать папку мало. Копия прежнего файла ляжет в `.workplace/backup-update` |
| В плане «УДАЛЁН» | Файл пакета удалили. Он не восстанавливается сам: после «да» человека на этот файл (имя или путь, либо файл в плане) добавь `--overwrite путь` |
| «Пакет лежит внутри главной папки» | Распакуй архив в Загрузки, а не внутрь главной папки |
| Нет сумм или сумма не совпала | Не распаковывай. Скачай ещё раз; не помогло: покажи человеку обе суммы и объясни, что архив не тот |

## Известные ограничения

- Сторож секретов и сторож опасных команд работают по тексту команды или записи. Это фильтры, а не стена: хитрой командой их можно обойти. Против невнимательного ИИ они достаточны, против злоумышленника нет.
- Известные обходы сторожа секретов, которые мы не закрываем: запись значения переменной окружения кодом интерпретатора (`node -e` с `process.env`, `python -c` с `os.environ`), запись значения через `Set-Content` из переменной окружения и склейка имени файла из частей. Они названы в шапке сторожа («фильтр, а не стена»): модель угрозы это обычный человек и невнимательный ИИ, не злоумышленник.
- Сторож кросс-проверки сверяет файлы с манифестом по sha256 (исчезнувший файл считается изменённым), а принятую проверку засчитывает, только если есть `run.json` от `run-check.js`. Но `run.json` тоже файл: защита от невнимательного агента, не от злоумышленника.
- Подлог `run.json` и `verdict.md` с верными хешами, временем и проверяющим локально не закрывается принципиально: всё лежит в тех же файлах. Сторож останавливает запись инструментами и командами, включая `cd` с относительным путём, перенаправление и `node -e` или `python -c`, которые называют эти файлы; код в отдельном файле и имена, склеенные из частей, он не видит.
- Запись вне главной папки: сторож смотрит на инструменты записи (Write, Edit, MultiEdit, NotebookEdit, apply_patch) и ждёт «да» человека на цель. Команды оболочки и код на интерпретаторе (`cat >`, `node -e`, `python -c`) он проверяет в основном для профилей оболочки, `~/.ssh` и личных настроек ИИ; для остального это фильтр против невнимательного агента.
- Личные папки `~/.claude/skills`, `~/.claude/agents`, `~/.claude/commands`, `~/.codex/prompts` и `~/.codex/skills` инструментом записи не пишутся (там настройки самого человека): навыки этой установки лежат в главной папке (`.claude/skills` и `.agents/skills`). Нужен именно личный навык: покажи человеку, что запишешь, и после его «да» сделай запись командой оболочки.
- Постоянное доверие хукам Codex даёт только человек командой `/hooks`. Неинтерактивного способа без флага обхода доверия мы не нашли.
- У проверяющего нет границы чтения: он видит запрос и копии файлов. Поэтому секреты проверяющему не отправляются, а реальные почты и телефоны маскируются, пока нет решения человека (`checks/POLICY.md`).
- macOS 12 на раннерах GitHub Actions нет: этот случай проверяется только на живой машине.
- Проверка «хуки подхватились после перезапуска» и «Trust» делается по поведению ИИ в чате: автотеста у неё нет.
- Основной Codex на Windows и Mac: имена инструментов и поле `commandWindows` в хуках Codex не проверены живым запуском. Работают ли сторожа у конкретного человека, покажет проверка шага 9 установки.
- `~/.codex/config.toml`: когда человек доверяет папке и вводит `/hooks`, Codex сам дописывает разделы `[projects.*]` и `[hooks.state.*]`. Сверка показывает их как вопрос «это вы подтверждали?» (класс C), а не тревогу; другие разделы файла по-прежнему тревога. Что именно пишет Codex при подтверждении, на живом прогоне основного Codex не снималось (TODO: verify).

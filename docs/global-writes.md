# Что установка пишет вне главной папки

**Коротко:** установка пишет в главную папку и больше почти никуда. Всё, что она или программы пишут вне главной папки, делится на три класса. Перед установкой снимается копия списка файлов, после установки список сравнивается, и каждая запись попадает в свой класс. Тревогу даёт только запись, о которой никто не сказал заранее.

Это перечень записей самой установки. После установки человек может попросить ИИ изменить настройку, профиль оболочки, проект или поставить программу: такие записи делает ИИ по просьбе (копия файла, разница, «да» человека) и называет их в ответе. Сверка `snapshot diff` после этого покажет их как изменённые файлы: вопрос «это вы меняли?» тогда отвечается легко.

## Три класса записей

| Класс | Что это | Метка в сверке | Что делает ИИ |
|---|---|---|---|
| 1. Записи установщика | то, что пишет установка и официальные установщики программ, которые она запускает | `[D] объявлено`, если о записи сказали человеку заранее; `[A] ТРЕВОГА`, если нет | объявленное записывает в отчёт; по тревоге показывает запись человеку дословно, ничего не откатывает сам |
| 2. Штатные записи программ | журналы, кэш, файл входа и отметки самих Claude Code, Codex, npm | `[B] штатно` | пишет одной строкой в отчёт |
| 3. Файлы, которые мог менять человек или VS Code | настройки VS Code (он сам пишет их при Trust, перезапуске, ответах на свои вопросы) | `[C] вопрос: это вы меняли?` | показывает названия изменённых ключей (значения не печатаются) и спрашивает человека |

## Что и где записывается

### Класс 1. Записи установщика

| Что | Где | Когда |
|---|---|---|
| Главная папка целиком: `.workplace/`, `AGENTS.md`, `CLAUDE.md`, `STATE.md`, `tasks.md`, `MEMORY.md`, `.claude/`, `.codex/`, `.agents/`, `checks/`, `handoffs/`, `workspaces/`, `install-report.md` | новая папка, которую выбрал человек | `init`, `layout`, `hooks wire`, `report` (это не запись вне папки, указана для полноты) |
| Родительские папки пути главной папки, если их нет | выше главной папки | `init` |
| Скачанный архив и распакованный пакет | папка Загрузки, `workplace-installer-ВЕРСИЯ` | шаг 1 установки и обновление. Удалить их может человек, когда захочет |
| Claude Code (официальный установщик) | Mac `~/.local/bin/claude`, `~/.local/share/claude`; Windows `%USERPROFILE%\.local\bin\claude.exe`, `%USERPROFILE%\.local\share\claude`; установщик может дописать PATH в профиль оболочки | `wp.js install claude` |
| Codex CLI (официальный установщик) | Mac `~/.local/bin/codex`, `~/.codex/packages/standalone`, PATH в профиль; Windows `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin`, пользовательский PATH | `wp.js install codex` |
| Node, Python, git | Windows: Program Files. Mac: Node из архива nodejs.org в `~/.local/node` (без пароля; Homebrew только если он уже стоит и Mac его поддерживает, тогда `/opt/homebrew`), Python и git через Command Line Tools (системные папки Apple) | после «да», командами из плана |
| Кэш npm запасного пути | `.workplace/npm-cache` внутри главной папки | `wp.js install --npm` |
| Настройка VS Code `claudeCode.focusView` | файл настроек пользователя VS Code | модуль `vscode`, по «да» человека, с копией файла до записи |
| Профили оболочки: `~/.zprofile`, `~/.zshrc` | домашняя папка | строки PATH от официальных установщиков и команда `wp.js path-fix --yes --human-said "слова человека с «да»"` (по плану установки, с копией профиля в `.workplace/backup-profile` и объявлением записи) |

Перед запуском официального установщика, который правит профиль, ИИ говорит об этом человеку. Запись объявляется командой `state declare` (путь `~/файл`; для одного ключа файла настроек VS Code `~/файл#ключ`) и после установки проверяется на дубли.

### Класс 2. Штатные записи программ

| Что | Где |
|---|---|
| История чатов, отметка доверия к папке, служебные файлы Claude Code | `~/.claude/projects/`, `~/.claude.json`, `~/.claude/` |
| Вход Claude | Keychain на Mac; `~/.claude/.credentials.json` там, где Keychain недоступен, и на Windows |
| Сессии, журналы, кэш, файл входа Codex | `~/.codex/sessions/`, `logs`, `cache`, `*.sqlite`, `auth.json`. Файл `auth.json` меняется при каждом использовании Codex: это штатная запись |
| Кэш и журналы npm, если npm вызывали не мы | `~/.npm` |
| Список недавних папок и решения Trust | хранилище VS Code |

### Класс 3. Файлы, которые мог менять человек или VS Code

| Что | Где |
|---|---|
| Настройки пользователя VS Code | Mac `~/Library/Application Support/Code/User/settings.json`; Windows `%APPDATA%\Code\User\settings.json`; Linux `~/.config/Code/User/settings.json` |
| Доверие Codex папкам и хукам | `~/.codex/config.toml`, разделы `[projects.*]` и `[hooks.state.*]`: Codex пишет их сам, когда человек доверяет папке и вводит `/hooks`. Сверка видит это по разделам и показывает вопросом, значения не печатаются |

Если изменённые ключи похожи на наши (названия с claude, codex, mcp, hook, shell, команды запуска), сверка поднимает тревогу, а не вопрос. Файл `keybindings.json` всегда тревога: сочетание клавиш может запускать команды.

## Чего установка не пишет

Сама установка не создаёт и не меняет (после установки человек может попросить любое из этого, тогда ИИ делает это по просьбе):

- `~/.claude/settings.json`, `~/.claude/CLAUDE.md`, `~/.claude/skills`, `~/.claude/agents`, `~/.claude/hooks`;
- `~/.codex/config.toml`, `~/.codex/AGENTS.md`, `~/.codex/hooks.json` (модель по умолчанию, режимы и доверие не трогаются);
- глобальный и системный git config (имя и почта пишутся только локально в `.git` главной папки);
- файлы ваших других проектов и их git;
- `keybindings.json` VS Code.

Всё, что установка настраивает, лежит в главной папке и действует, только когда вы открываете её.

## Как это проверяется

```
node .workplace/core/cli/wp.js snapshot before    (снимается автоматически при init)
node .workplace/core/cli/wp.js snapshot after
node .workplace/core/cli/wp.js snapshot diff
```

- Отслеживаются профили оболочки, настройки Claude Code и Codex, настройки VS Code, `.gitconfig`, папки навыков, агентов и хуков в `~/.claude` и `~/.agents`, верхний уровень `~/.claude`, `~/.codex`, `~/.npm`, `~/.local`.
- Файлы с секретами по природе (`auth.json`, `.npmrc`, `.pypirc`, `.netrc`, `.git-credentials`, всё, что похоже на ключ) копируются не целиком: сохраняются только хеш и размер. Значения нигде не печатаются. Несекретные из отслеживаемых файлов (профили оболочки, настройки Claude Code, Codex и VS Code, `.gitconfig`) копируются в `.workplace/snapshots/before-files/` (права 0600, папка закрыта в `.gitignore`): это нужно, чтобы тревогу можно было откатить копией. Если копия вам не нужна, удалите папку `before-files` после сверки.
- Код выхода `snapshot diff` равен 1, только если есть записи класса `[A]`.
- Итог сверки попадает в `install-report.md`, раздел «Изменения вне главной папки».

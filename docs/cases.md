# Четыре случая и два направления

**Коротко:** разведка не меняет ничего и относит машину к одному из четырёх случаев. По случаю она предлагает направление: кто делает и кто проверяет. Человек подтверждает одним словом. Ставится только недостающее. Оба направления рабочие: основной может быть Claude Code или Codex, и человек меняет его одной фразой («сделай основным Codex»). Этот файл описывает установку; после неё хозяин человек (правила в `AGENTS.md` главной папки).

## Как разведка определяет случай

| Случай | Условие |
|---|---|
| Пусто | нет ни Claude Code, ни Codex: ни консольных программ, ни расширений |
| Только Claude Code | Claude Code есть (консольный или в расширении), Codex нет |
| Только Codex | Codex есть (консольный или в расширении), Claude Code нет |
| Всё есть, но разбросано | есть и то и другое; или копий одной программы больше одной; или программа лежит вне PATH |

Правило то же, что в `core/lib/recon.js` (функция `detectCase`) и в `docs/recon-without-node.md`.

Расширение Codex в VS Code консольным Codex не считается. В таблице это две отдельные строки: «расширение Codex: есть», «консольный codex: нет». Проверяющему нужна именно консольная программа: установщик запускает её сам, чтобы проверить работу основного ИИ.

## Что делает установщик в каждом случае

### Пусто

- Что видит разведка: ни одного из двух ИИ. Часто нет и Node.
- Что ставится: Node, Python, основной ИИ, второй ИИ. Git по «да».
- Что делает человек: пароль и окно UAC, если их попросят; вход в оба аккаунта в браузере.
- Предлагаемое направление: основной Claude Code, проверяет Codex.

### Только Claude Code

- Что видит разведка: Claude Code уже работает, консольного Codex нет.
- Что ставится: консольный Codex (и Node с Python, если их нет). Claude Code не трогается.
- Что делает человек: вход в ChatGPT в браузере.
- Предлагаемое направление: основной Claude Code, проверяет Codex.

### Только Codex

- Что видит разведка: Codex работает, Claude Code нет.
- Что ставится: Claude Code (и Node с Python, если их нет). Codex не трогается.
- Что делает человек: вход в аккаунт Claude в браузере.
- Предлагаемое направление: основной Claude Code (он будет поставлен), проверяет Codex. Если человек хочет основным Codex, проверять будет Claude Code: он скажет «наоборот», и ставится так.

### Всё есть, но разбросано

Пример. У человека стоят VS Code, расширения Claude Code и Codex, консольный `claude`, Python и git, рядом много своих проектов. Консольного Codex нет: есть только расширение и файл входа.

- Что видит разведка: оба ИИ есть, но копий несколько, или программа вне PATH, или Codex только как расширение.
- Что ставится: недостающее. Если консольного Codex нет, ставится он. Старые копии `claude` не удаляются и не обновляются без «да».
- Что делает человек: вход, если его нет. Если вход в ChatGPT от расширения уже есть, консольный Codex использует тот же вход, второй раз входить не нужно (проверяется командой `codex login status`).
- Особые правила установки: список «не трогаю» с папками проектов (только на время установки); предупреждение, если macOS старше 13; две копии одной программы показываются, но не меняются.
- Предлагаемое направление: основной Claude Code, проверяет Codex. Основной Codex по просьбе человека.

## Что ставится по случаям и направлениям

| Случай | Основной Claude Code, проверяет Codex | Основной Codex, проверяет Claude Code |
|---|---|---|
| Пусто | Node, Claude Code, Codex CLI, вход в оба | Node, Codex CLI, Claude Code, вход в оба |
| Только Claude Code | (Node), Codex CLI, вход в ChatGPT | ставится Codex, Claude Code становится проверяющим |
| Только Codex | ставится Claude Code, Codex становится проверяющим | (Node), Claude Code, вход в Claude |
| Разбросано | консольный Codex, если его нет; чужие копии не трогаются | консольный Claude Code, если его нет; чужие копии не трогаются |

Python и git: Python обязателен, git ставится по «да».

## Чем отличаются направления

Всё различие живёт в одном месте, `core/providers`. В `.workplace/config.json` два поля: `main` и `reviewer`. Проверяет по умолчанию другой ИИ. Сменить роли после установки: `wp.js role set <claude|codex>`; команда меняет конфиг, `AGENTS.md`, сторожей и навыки сразу. Любой из двух ИИ может получить задачу на исполнение, а не только на проверку.

| Что | Основной Claude Code | Основной Codex |
|---|---|---|
| Кто проверяет | Codex: `codex exec --sandbox read-only --ephemeral --skip-git-repo-check`, запрос идёт через stdin | Claude Code: `claude -p` с инструментами `Read,Grep,Glob`, режимом `dontAsk`, без сохранения сессии и без чужих настроек (`--setting-sources ""`) |
| Правила | `CLAUDE.md` со строкой `@AGENTS.md`; правила лежат в `AGENTS.md` | Codex читает `AGENTS.md` сам |
| Сторожа | `.claude/settings.json`, пути через `$CLAUDE_PROJECT_DIR` | `.codex/hooks.json`, пути абсолютные; нужны `.git` в корне и разовое доверие командой `/hooks` |
| Навыки | `.claude/skills/` | `.agents/skills/` (те же файлы, байт в байт) |
| Проверка входа | `claude auth status` (только после «да»: команда создаёт файлы) | `codex login status` |
| Вызов проверяющего | обычный запуск из Bash | Claude вызывается из песочницы Codex, а ей нужна сеть: `wp.js layout` пишет `.codex/config.toml` с `[sandbox_workspace_write]` и `network_access = true` (запасной путь: запуск Codex с `-c sandbox_workspace_write.network_access=true`); без сети `run-check.js` за несколько секунд отвечает «нет сети». Сторожа Codex на Windows и Mac живым запуском ещё не обкатаны, их покажет проверка шага 9 |
| Правило «сильная модель пишет задание, средняя делает» | включено | выключено: у Codex нет такого механизма |

## Что остаётся за человеком в любом случае

Вход в аккаунты, пароль компьютера, окно UAC, системное окно Command Line Tools на Mac, разовое доверие хукам Codex. Homebrew на Mac для установки не нужен (на Intel и на macOS ниже 15 он не поддерживается): если он нужен человеку для других программ, команду с https://brew.sh он запускает сам. Полный список: раздел «Что вы делаете руками» в [README](../README.md).

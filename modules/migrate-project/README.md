# Модуль migrate-project: перенос старого проекта в главную папку

**Коротко:** команда `migrate-project` делает копию вашего проекта в `projects/ИМЯ` главной папки вместе с историей git. Перед копией она делает резервную копию, после копии сверяет всё с исходником. Старый проект она не меняет и не удаляет.

Это один из способов, не единственный. Работать с проектом можно на месте (копия файла перед правкой и ваше «да» на папку) или в папке, которую вы сами скопировали в главную папку (`wp.js adopt <путь>`). Модуль нужен, когда вам важна копия именно с историей git и сверкой. Установка ничего не переносит.

## Условия

- Сначала чтение (`inspect`): ИИ показывает, что за проект и что нужно учесть.
- Копия запускается с `--yes`. Без него команда показывает план и ничего не пишет (код выхода 2). Вы сами попросили копию: ИИ показывает план и сразу запускает с `--yes`. Копию предложил ИИ: сначала план и ваше «да».
- Команда запускается только из главной папки: `.workplace/modules/migrate-project/migrate-project.js`. Параметра «куда писать» нет, главную папку скрипт определяет по своему месту.

## Команды

```
node .workplace/modules/migrate-project/migrate-project.js inspect ПАПКА_ПРОЕКТА
node .workplace/modules/migrate-project/migrate-project.js copy ПАПКА_ПРОЕКТА --name ИМЯ
node .workplace/modules/migrate-project/migrate-project.js copy ПАПКА_ПРОЕКТА --name ИМЯ --yes
node .workplace/modules/migrate-project/migrate-project.js verify ПАПКА_ПРОЕКТА --name ИМЯ
```

- `inspect` только читает и работает откуда угодно. Показывает: git это или нет, ветку, удалённые адреса (без паролей), незакоммиченные правки, отложенные правки (stash), файлы ключей рядом (значения не читает), размер, тяжёлые папки. Печатает `СТОП`, если копия невозможна технически (причины в таблице ниже); тогда работайте с проектом на месте. Параметр `--json` печатает то же в JSON.
- `copy` без `--yes` показывает план. С `--yes`: резервная копия, копия, сверка.
- `verify` повторно сверяет копию с исходником. Параметр `--full` сверяет все файлы по содержимому (без него до 5000 файлов и 500 МБ сверяются полностью, больше выборкой).
- Имя папки: латиница в нижнем регистре, цифры и дефис (`lead-agent`). Без `--name` берётся из названия папки проекта.
- Параметр `--include-heavy` копирует и тяжёлые папки (`node_modules`, `.venv` и подобные). По умолчанию в git-проекте они пропускаются, если git их игнорирует: они восстанавливаются установкой зависимостей. В проекте без git копируется всё.

## Что делает `copy --yes`

1. Проверяет, что проект переносить можно, и что места хватит (нужно примерно вдвое больше размера проекта).
2. Делает резервную копию в `.workplace/backup-update/migrate-ИМЯ-МЕТКА/project`. Эта папка не попадает в git главной папки. Удалить её может сам человек, когда убедится, что всё работает.
3. Копирует проект в `projects/ИМЯ`: историю git, ветки, удалённые адреса, отложенные правки и незакоммиченные правки. Ничего не коммитится.
4. Сверяет: тот же коммит и ветка, те же адреса, тот же список незакоммиченного, `git fsck` без ошибок, состав и содержимое файлов, совпадение с резервной копией, исходник не менялся с начала копирования, git главной папки не видит проект.
5. Пишет запись в `STATE.md` через `wp.js state log`.

Если копирование прервалось, неполные копии удаляются, исходная папка не тронута.

## Когда команда отказывается

| Что видно | Почему |
|---|---|
| `СТОП: .git здесь файл` | Подмодуль или дополнительное рабочее дерево: копия потеряла бы связь с историей |
| `СТОП: core.worktree` | Репозиторий привязан к конкретной папке: коммит из копии задел бы исходный проект. Настройку может убрать только владелец проекта |
| `СТОП: папка внутри репозитория` | Перенос подпапки потерял бы историю. Назовите корень репозитория |
| «Проект уже внутри главной папки» | Переносить нечего |
| «Главная папка лежит внутри этого проекта» | Копия скопировала бы саму себя |
| «projects/ИМЯ уже есть» | Существующую копию команда не перезаписывает: возьмите другое имя |
| Нет места | Освободите место: копии нужно вдвое больше размера проекта |

## Что учесть

- Незакоммиченные правки копируются как есть и остаются незакоммиченными.
- `.env` копируется как есть (это ваши данные). Если git проекта его не игнорирует, `inspect` предупредит.
- Чаты Claude Code привязаны к пути папки: начатые в старой папке в новой не появятся. Память проекта (`CLAUDE.md`) переносится вместе с файлами.
- В исходном проекте команда ничего не создаёт и не запускает, git там вызывается только на чтение.
- Старый проект после копии остаётся на месте. Удалить его можно по вашей просьбе: ИИ покажет полный путь и спросит «да».

## Проверка

`node modules/migrate-project/migrate-project.test.js` из пакета. Тест строит временные репозитории и фейковую главную папку (папка для них: `WP_TEST_TMP` или временная папка ОС) и требует установленный git.

# История версий

## 4.0.0-rc.1

Тестовый выпуск: может сломаться; если не получилось, пришлите отчёт (необязательно, см. README). Изменений относительно сборки 4.0.0-dev нет, кроме номера версии и адресов выпуска.

Универсальный установщик. Заменяет серию 3.x, которая была рассчитана на одну машину и один случай.

Что нового:

- Согласие на установке без сторожа сообщений (этап Q): цитата `--human-said` не выдаётся за доказательство, в `install-report.md` и `state.json` запись идёт с пометкой «подтверждено запросом разрешения программы, а не механизмом пакета» (`verified: false`); INSTALL.md запрещает ИИ включать режимы без запросов и просить об этом человека. Оценщик приёмочного стенда стал строгим и проверяется без моделей (`tests/acceptance/grader.test.js`).
- Согласие только от человека (этап N): `update apply` берёт «да» из записанных сообщений человека (в последнем «да», в двух последних «обнови»/«update» или версия, либо принятый план), `--overwrite` требует назвать каждый файл, `--human-said` у `update` не принимается; модуль vscode (`apply --yes`, `revert --yes`) проверяет «да» и название VS Code так же; `layout --update` перед заменой навыка кладёт копию прежнего в `.workplace/backups`.
- Приёмка по договору поведения (этап М): команда `wp.js backup`; `install` и `path-fix` не принимают один флаг `--yes` за «да» человека (нужны сообщение человека при подключённом сторожe либо `--human-said` со словами человека, они попадают в отчёт); сторож понимает переменную пути в PowerShell и круглые скобки в `(cd папка && команда) > файл`; «VS Code» называет файл настроек; `claude update --help` и Glob по `.env` больше не останавливаются; вложенный проект со своим `.git` закрывается в `.gitignore` главной папки хуком на сообщение человека; формулировка про основной Codex без «экспериментально».

- Вход: один файл INSTALL.md для ИИ и одна фраза в README. Скачивание архива выпуска со сверкой sha256. Git и исполняемые файлы для входа не нужны.
- Разведка определяет случай: пусто, только Claude Code, только Codex, всё есть но разбросано. Консольный Codex и расширение Codex в VS Code считаются разными вещами.
- Оба направления проверки: Claude Code делает и Codex проверяет, или Codex делает и Claude Code проверяет. Различие собрано в одном месте, `core/providers`.
- Установка недостающего после одного «да»: Node, Python, основной и второй ИИ, git (по «да»). Пароль, окно UAC, Homebrew и входы в аккаунты делает человек.
- Главная папка живёт рядом с меткой `.workplace/`. Всё, что вне неё, делится на три класса записей: сделанное установщиком, штатное и файлы, которые мог менять человек или VS Code.
- Сторожа: секретов (проверяет и содержимое записи), старта сессии, опасных команд, напоминатель правила, кросс-проверки перед необратимым шагом. Один скрипт на оба ИИ.
- Навыки: `/cross-check`, `/end-session`, `/new-workspace`, `/doctor`.
- Проверка сторожа выдуманным паролем и самопроверка с вшитой ошибкой в обоих направлениях.
- Обновление по фразе «обнови установщик»: план, потом применение после «да», правки человека не затираются.
- Модуль `migrate-project`: копия старого проекта с историей git, резервная копия до, сверка после, запуск только по отдельному «да».
- Модуль `vscode`: порядок шагов для редактора и настройка `claudeCode.focusView` («Claude Code: Toggle Focus view»).
- Проверки перед публикацией: `scripts/check-no-private.js` и `scripts/build-release.js`. Тесты на macOS и Windows в GitHub Actions.

Исправления по проверке сборки (этап Г):

- Самопроверка больше не подделывается: вердикт принимается, только если рядом лежит `run.json` от настоящего запуска проверяющего (проверяющий, код выхода, время, хеши); запись в служебные файлы проверок останавливает сторож.
- Сторож опасных команд видит запись инструментами (Write, Edit, MultiEdit, NotebookEdit, apply_patch): профили оболочки, `~/.ssh`, личные настройки и всё вне главной папки.
- Основной Codex: `layout` пишет `.codex/config.toml` с сетью для песочницы, проверяющий Claude без сети отвечает «нет сети» за секунды. Первым выпускается направление «основной Claude Code»: разведка всегда предлагает его.
- `update` отличает правки человека по хешу установленной версии: правленый файл не затирается, удалённый не восстанавливается без «да».
- Разведка не создаёт `~/.codex/tmp`; `verify all` не включает отчёт; доверие Codex папкам и хукам в `config.toml` это вопрос «это вы подтверждали?», а не тревога; после установки программ печатается полный путь и есть ли папка в PATH, а команда `wp.js path-fix` дописывает PATH в профиль только по «да» (путь Mac без Homebrew этого пункта заменён этапом Ж, см. ниже).
- Живой прогон проверяющего: `tests/live/real-reviewer.js` (ручной, тратит лимит подписки).

Исправления по повторной проверке (этап Ж):

- Mac: Homebrew больше не основной путь. Он поддерживается только на Apple Silicon с macOS 15 и новее (Intel это Tier 3, источник docs.brew.sh на 21.10.2026), поэтому на остальных Mac Node ставится официальным архивом с nodejs.org в `~/.local/node` скриптом `core/scripts/install-node-user.sh` (без пароля, sha256 по SHASUMS256.txt, Node 24 на macOS 13.5 и новее, Node 22 на macOS 11 - 13.4), Python и git приносят Command Line Tools. `wp.js path-fix` дописывает и папку этого Node, с предупреждением.
- Сторожа: чтение служебных файлов проверки (`sed -n`, `jq`, `shasum` и подобные) не отказ; `wp.js state log` с `~/.zshrc` в тексте не отказ; обход через `cd` и относительный путь, `node -e` и `python -c` закрыт; отказ записи в личные `~/.claude/skills` и `~/.claude/agents` объясняет, что навыки ставятся в главную папку.
- `update`: без записи хешей любое отличие это «ОТЛИЧАЕТСЯ», файлы, ушедшие из пакета, называются «устарел, не удаляю»; `snapshot`: неизвестный ключ внутри доверия Codex это тревога; проверяющий Claude за прокси не получает ложного «нет сети».

Тексты для ИИ переписаны заново по договору поведения (CONTRACT.md): два этапа (установка и обычная работа), три ограничения вместо россыпи запретов. После установки хозяин человек: ИИ читает и правит его проекты на месте или в копии, отдаёт задачу второму ИИ, ставит и обновляет программы, правит настройки, делает коммит и push, использует ключ из .env, меняет основной ИИ. Установка: одно «да» на весь план, оба направления, обратная связь автору необязательна. Тексты ждут от ядра команды `wp.js adopt`, `wp.js role set`, `wp.js backup`, `wp.js consent plan`.

Что убрано относительно 3.x:

- Все текстовые запреты против собственной установки и режим, где установку ведёт помощник-человек.
- Запрет `claude update` целиком (теперь обновление только по «да»).
- Поиск Codex внутри расширения VS Code.
- Хук `no-promise` (давал много ложных срабатываний).
- Исполняемые файлы для двойного щелчка.
